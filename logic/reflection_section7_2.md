# Section 7.2: Reflection (Prolog)

**1. What is the difference between a Prolog fact and a Prolog rule?**
A fact (e.g. `connected(a,b).`) is an unconditional statement asserted to be true.
A rule (e.g. `can_move(X,Y) :- connected(X,Y).`) states that its head is true
*conditionally*, provided its body can be proven true — it defines how new truths
can be derived from existing facts/rules rather than asserting one directly.

**2. How does a Prolog query correspond to asking whether something follows from a
knowledge base?**
A query `?- Goal.` asks Prolog to determine whether `Goal` is a logical consequence
of the facts and rules currently loaded — i.e., whether the knowledge base entails
`Goal`. Prolog answers by attempting SLD-resolution (backward chaining) from the
goal to the facts; success means the knowledge base entails the goal, failure means
it does not.

**3. Why might it be useful to use a Prolog program to verify a plan generated by
a Python program?**
Prolog gives an independent implementation of the domain's logical facts and
rules, evaluated by a different mechanism (SLD-resolution) than the Python
planner's BFS. If both agree, that is stronger evidence of correctness than
trusting a single implementation; if they disagree, it flags a bug in one of them
(e.g. the Python planner proposing an action not actually licensed by the domain
facts).

**4. What advantage does an independent verifier provide when the original plan
was generated with the help of an LLM?**
LLM-generated code or explanations can look correct while containing subtle
errors (wrong precondition check, off-by-one action, hallucinated fact) that are
easy to miss by re-reading. An independent verifier written from the same
specification but implemented separately (different language, different
mechanism) has no shared blind spots with the generator, so it can catch mistakes
that inspecting the generator's own output or explanation would not reveal.

**Key idea:** An AI system can generate a candidate solution, while a separate
logical system checks it.
